Your Goal開発中

目標を宣言し、進捗や達成を報告しながら、いいね・コメントで互いの挑戦を応援し合えるSNS型のWebアプリ。

機能
目標宣言 / 進捗報告 / 達成報告 / 学び・知識の共有 / タイムライン（おすすめ・新着） / いいね・コメント / 管理者によるユーザー・投稿・コメント管理
技術
PHP 8.3、Laravel 13、Laravel Fortify、MySQL、PHPUnit、Laravel Debugbar、Docker（Laravel Sail）
担当
設計・バックエンド、フロントエンドの実装

開発で意識している点

「人が自ら行動し、挑戦を続けられる仕組みを作りたい」という思いから、自分で企画したアプリです。これまでの2作品で得た学びを活かし、「作る前に考える」「小さく積み上げる」「使う人の目線で守る」ことを意識して開発しています。また、自分以外の人が読む・引き継ぐことを前提に、チーム開発や運用を見据えたコードを書くことを特に大切にしています。

  • 作る前に全体像を固める：book_shelfで作業順に迷った反省から、設計書をもとに全ルートを先に定義し、コントローラーを空のメソッドで用意してから実装に入るようにしました
  • 機能ごとに小さく積み上げる：1つの機能ごとにブランチを切り、Pull Requestで変更内容を説明できる単位にまとめてからマージしています
  • データの矛盾を仕組みで防ぐ：同じ投稿への二重いいねは複合ユニーク制約で、達成報告と目標の「達成済み」への変更はトランザクションで一括処理するなど、誤操作が起きても壊れない作りを意識しています
  • 先にテストできる土台を作る：実装の前にFactoryとSeederを整え、管理者機能などはFeatureテストで動作を確認しています
  • 運用を見据えてクエリ問題を残さない：データが増えても重くならないよう、Laravel Debugbarで発行されるクエリを確認しながら実装しています。タイムラインではコメント数の取得で起きていたN+1問題を、Eager Loadingで解消しました
  • チームで読みやすいコードにする：Pintで書き方を統一したうえで、処理の意図が伝わりにくい箇所には「なぜこう書いたか」をコメントでこまめに残し、他の人が読んでも迷わない状態を意識しています
  • AIのコードは理解してから使う：Claude Codeを活用しつつ、提案されたコードはそのまま使わず、意図や動きを一度しっかり理解してから取り込んでいます
